# GotLem (GitLab Golem) Specification

GotLem is a tool designed to identify and correct issues/epics in GitLab that do not adhere to specific management rules. It does so by proposing comments with GitLab quick actions.

## Core Components

### 1. Configuration (YAML)
The tool is driven by a YAML configuration file:
- `gitlab_url`: The base URL of the GitLab instance.
- `scope`:
    - `groups`: List of group paths.
    - `projects`: List of project paths.
- `comment_prefix`: Text added before every generated comment.
- `comment_suffix`: Text added after every generated comment.
- `rules`: A list of rules to evaluate against issues and epics.

### 2. Rule Definition
Each rule consists of:
- `name`: A descriptive name for the rule.
- `version`: A version number (integer).
- `perimeter`: A Handlebars template expression that evaluates to a boolean.
- `comment`: A Handlebars template text for the comment body.

#### Perimeter Functions
- `hasNoMilestone()`: Returns true if the issue/epic has no milestone assigned.
- `hasLabel(label)`: Returns true if the issue/epic has the specified label.
- Supports logical operators `and` and `or`.

#### Comment Functions
- `getCurrentMilestone()`: Returns the title of the currently open milestone for the project.
    - **Error Condition**: If 0 or >1 milestones are open, the rule application fails with an error.

### 3. Workflow
1. **Fetch**: The tool retrieves all issues and epics from the specified groups and projects.
2. **Analyze**: Each item is checked against the rules.
3. **Report**: An HTML report is generated listing proposed changes.
4. **Review**: The user views the report in a browser.
5. **Execute**: The user provides a Personal Access Token (PAT) and confirms individual comments to be posted.

## Technical Requirements
- **Language**: TypeScript.
- **Dependencies**: Minimal (e.g., `js-yaml`, `handlebars`, `axios` or similar for API).
- **Interface**: HTML report with interactive elements to post comments via GitLab API.

## YAML Configuration Example
```yaml
gitlab_url: "https://gitlab.com"
scope:
  groups:
    - "my-organization/core-team"
    - "my-organization/research-lab"
  projects:
    - "my-organization/side-project/ui-lib"
    - "my-organization/utils/logger"
comment_prefix: "### GotLem Analysis\n"
comment_suffix: "\n\n_Auto-generated by GotLem_"
rules:
  - name: "No Milestone"
    version: 1
    perimeter: "{{#if (hasNoMilestone)}}true{{/if}}"
    # Note: %"Milestone Name" is standard GitLab syntax for milestones in quick actions
    comment: "This issue has no milestone. Please assign the current milestone: /milestone %\"{{getCurrentMilestone}}\""
  - name: "Bug No Milestone"
    version: 1
    perimeter: "{{#if (and (hasLabel 'bug') (hasNoMilestone))}}true{{/if}}"
    comment: "Bugs must have a milestone. Assigning: /milestone %\"{{getCurrentMilestone}}\""
```

> [!NOTE]
> In GitLab quick actions, milestones are referenced using the `%` prefix. If the milestone name contains spaces, it should be enclosed in double quotes (e.g., `/milestone %"Current Milestone"`). The `{{getCurrentMilestone}}` helper provides the name, and the template handles the GitLab-specific formatting.
